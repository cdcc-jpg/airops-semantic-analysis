End-to-End Classification Pipeline

How Facettes maps raw physical data columns to integrated semantic triples via dense vector retrieval and OWL domain constraints.

01

Raw Silos Ingestion

Facettes ingests raw database columns, CSV sheets, Markdown streams, and JSON-LD catalogs. It builds a local Layer 2 graph representing the raw data schema exactly as it stands without manual column renaming.

# Raw JSON-LD block (Silo 1 Catalog): { "@type": "Product", "sku": "SKU-0001", "name": "Novritsch SSG10", "brand": { "name": "Novritsch" } }
02

Stage 1: Bi-Encoder Candidate Retrieval Neural

The bi-encoder (all-MiniLM-L6-v2) embeds L2 raw schema names and L1 target ontology concepts into vector space. Cosine similarity retrieves candidate matches segregated by schema kind to prevent cross-kind crowding.

Embedding L2 "brand name manufacturer"... Embedding L1 "has brand"... Cosine Similarity: 0.6020 (Candidate Accepted)
03

Stage 2: Domain-Guided Structural Assembly Logical

Reads OWL target ontology constraints (rdfs:domain and rdfs:range) to group candidates by their logical class domain, resolves ObjectProperty links (asoft:repairedReplica), and compiles a SPARQL CONSTRUCT query.

Activated domains: [AirsoftReplica, RepairInvoice] Grouping properties under domains: -> AirsoftReplica: has brand, has model name -> RepairInvoice: repair ID Resolved Link: RepairInvoice -> repairedReplica -> AirsoftReplica
04

Stage 3: Cross-Encoder Re-Ranking Neural

Drafts candidate mappings across activated target domains, enriches class labels with mapped attribute sets, and computes pairwise cross-attention scores (ms-marco-MiniLM-L-6-v2) to filter out false matches.

Input Pair to Cross-Encoder: Sentence A: "Retail Item Record (attributes: item replica model name, brand name manufacturer)" Sentence B: "Airsoft replica (attributes: has model name, has brand)" Cross-Encoder Output Confidence: 0.8647 (Verified)
05

Stage 4: SPARQL Query Virtualization

Executes the validated SPARQL CONSTRUCT mapping query over the local Layer 2 data graph, translating raw database attributes into canonical RDF triples under governed namespaces.

CONSTRUCT { ?airsoftReplica a h:AirsoftReplica ; h:hasBrand ?brand_name . } WHERE { ?source src:brand_name ?brand_name . }
06

Stage 5: Identity Resolution & KG Merging

Merges translated silo graphs into a unified Knowledge Graph. Entity resolution aligns shared keys (such as Player index P_0001) via owl:sameAs assertions to form coherent cross-silo facets.

# Materialized identity linkage: asoft:Player_P_0001 owl:sameAs <http://example.org/inst/Player_P_0001> . <http://example.org/inst/ChronoEvent_0001> asoft:isOwnedBy asoft:Player_P_0001 .

Architectural Rationale for Semantic Graphs

Relational schemas isolate operational records across incompatible tables. Formal ontologies and RDF graphs provide identity continuity, declarative validation, and schema-free extensibility.

Automatic Identity Linking

In relational databases, joining client rosters, chronograph CSVs, workshop repair logs, and chat streams requires fragile ETL pipelines that break whenever an upstream column changes.

≠ Avoid · Brittle SQL Joins
Requires rigid foreign-key coupling and manual table migrations whenever upstream schemas evolve.
⊢ Clear · Dynamic owl:sameAs Resolution
Uses canonical IRIs (asoft:Player_P_0001) to represent the real-world bearer, aligning cross-silo facets dynamically.

Declarative Safety Verification

Checking whether a replica exceeds muzzle energy limits across field zones typically scatters imperative if/else branches across backend endpoints.

≠ Avoid · Hardcoded Imperative Checks
Safety and chronograph rules remain buried inside application code, requiring redeployment when field rules change.
⊢ Clear · Declarative SHACL Shapes
Constraints are governed as auditable RDF shapes evaluated directly against the dataset without modifying backend code.

Open-World Extensibility

Relational tables enforce a Closed-World schema where unanticipated attributes require destructive ALTER TABLE migrations and ORM refactors.

≠ Avoid · Closed-World Table Migrations
Onboarding unstructured sources forces schema alterations across downstream views and pipelines.
⊢ Clear · Open-World Triple Composition
New assertions (such as social stream mentions) merge directly into the triple store for immediate SPARQL traversal.
